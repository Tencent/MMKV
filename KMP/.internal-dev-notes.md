# KMP internal development notes

This file is for maintainers/debugging only. Keep user-facing setup and release information in `README.md` and `CHANGELOG.md`.

## Darwin dependency path

KMP Darwin no longer uses CocoaPods. iOS/macOS targets use the same `Core/cbridge/MMKVBridge.h` cinterop path as other Kotlin/Native targets.

Relevant files:
- `KMP/mmkv/build.gradle.kts` wires Darwin cinterop and CMake builds.
- `KMP/mmkv/nativeInterop/cinterop/mmkv.def` declares the C bridge header/static library and Darwin linker options.
- `KMP/mmkv/src/darwinMain/kotlin/com/tencent/mmkv/kmp/MMKV.darwin.kt` wraps the C bridge.
- `KMP/mmkv/src/darwinMain/kotlin/com/tencent/mmkv/kmp/MMKVNameSpace.darwin.kt` wraps namespace APIs through the C bridge.

## Dependency source overrides

Inside the monorepo, CMake uses local MMKV source. Outside the monorepo, CMake can fetch via:
- `MMKV_GIT_REPOSITORY`
- `MMKV_GIT_TAG`
- `MMKV_GIT_BRANCH`
- `MMKV_GIT_COMMIT`

Do not reintroduce `MMKV_POD_SOURCE`; it was only for the old CocoaPods cinterop path.

## Darwin lifecycle debugging

The old ObjC/CocoaPods wrapper path could crash after `MMKV.close()` plus `removeStorage()` because Kotlin/Native GC later released an ObjC `MMKV` wrapper whose native pointer had been invalidated elsewhere. Moving Darwin KMP to the C bridge avoids the ObjC wrapper lifetime path.

If a similar crash appears, inspect whether a Kotlin wrapper still references a native handle after `mmkv_close()` or `removeStorage()` has destroyed the underlying instance.

## JVM desktop ABI reminder

JNA `Boolean` does not match C `bool` ABI. For C bridge calls from JVM desktop:
- use `Byte` for C `bool` parameters,
- use `Byte` for C `bool` fields in `Structure`,
- convert Kotlin booleans with `toNativeByte()`.

This matters for encryption paths such as `mmkv_rekey()` and `MMKVConfig_t.aes256`.

## Publishing workflow

The KMP root dependency is intended to be one-dependency for consumers:

```kotlin
implementation("com.tencent:mmkv-kmp:<version>")
```

The JVM desktop variant (`mmkv-kmp-desktop`) declares runtime dependencies on all host-specific desktop native runtime artifacts:

- `mmkv-kmp-desktop-native-macos-arm64`
- `mmkv-kmp-desktop-native-macos-x86_64`
- `mmkv-kmp-desktop-native-linux-x86_64`
- `mmkv-kmp-desktop-native-linux-arm64`
- `mmkv-kmp-desktop-native-windows-x86_64`

That means all desktop-native runtime artifacts must be published before the release is considered usable.

### Credentials

Publishing uses the Gradle properties already wired in `KMP/mmkv/build.gradle.kts`:

- `RELEASE_REPOSITORY_URL` / `SNAPSHOT_REPOSITORY_URL`
- `SONATYPE_NEXUS_USERNAME` or `mavenCentralUsername`
- `SONATYPE_NEXUS_PASSWORD` or `mavenCentralPassword`
- `SIGNING_KEY` or `signingInMemoryKey`
- `SIGNING_PASSWORD` or `signingInMemoryKeyPassword`

Use `VERSION_NAME` and `MMKV_VERSION` in `KMP/gradle.properties` as the release source of truth.

### Dry-run locally

Use Maven Local before staging:

```bash
cd KMP
./gradlew :mmkv:publishToMavenLocal --stacktrace
```

For a focused desktop-runtime metadata check:

```bash
./gradlew :mmkv:generateMetadataFileForDesktopPublication :mmkv:generatePomFileForDesktopPublication --stacktrace
grep -R "mmkv-kmp-desktop-native" mmkv/build/publications/desktop
```

Both `module.json` and `pom-default.xml` should list all desktop-native runtime artifacts.

### Release host matrix

Publish to the same staging repository from each host. Avoid publishing the same coordinate twice from different hosts.

#### Primary host, usually macOS with Android SDK

Publishes common metadata, Android, JVM desktop, iOS, macOS, and one macOS desktop-native runtime for the host architecture:

```bash
cd KMP
./gradlew \
  :mmkv:publishKotlinMultiplatformPublicationToSonatypeRepository \
  :mmkv:publishAndroidPublicationToSonatypeRepository \
  :mmkv:publishDesktopPublicationToSonatypeRepository \
  :mmkv:publishIosArm64PublicationToSonatypeRepository \
  :mmkv:publishIosSimulatorArm64PublicationToSonatypeRepository \
  :mmkv:publishIosX64PublicationToSonatypeRepository \
  :mmkv:publishMacosArm64PublicationToSonatypeRepository \
  :mmkv:publishMacosX64PublicationToSonatypeRepository \
  :mmkv:publishDesktopNativePublicationToSonatypeRepository \
  --stacktrace
```

On Apple Silicon this publishes `mmkv-kmp-desktop-native-macos-arm64`. To publish `mmkv-kmp-desktop-native-macos-x86_64`, run `publishDesktopNativePublicationToSonatypeRepository` on an Intel macOS host, or under an x86_64 JDK/Rosetta environment where `os.arch` reports x86_64.

#### Linux x86_64 host

```bash
cd KMP
./gradlew \
  :mmkv:publishLinuxX64PublicationToSonatypeRepository \
  :mmkv:publishDesktopNativePublicationToSonatypeRepository \
  --stacktrace
```

This publishes `mmkv-kmp-linuxx64` and `mmkv-kmp-desktop-native-linux-x86_64`.

#### Linux ARM64 host

```bash
cd KMP
./gradlew \
  :mmkv:publishLinuxArm64PublicationToSonatypeRepository \
  :mmkv:publishDesktopNativePublicationToSonatypeRepository \
  --stacktrace
```

This publishes `mmkv-kmp-linuxarm64` and `mmkv-kmp-desktop-native-linux-arm64`.

#### Windows x86_64 host

```powershell
cd KMP
.\gradlew.bat `
  :mmkv:publishMingwX64PublicationToSonatypeRepository `
  :mmkv:publishDesktopNativePublicationToSonatypeRepository `
  --stacktrace
```

This publishes `mmkv-kmp-mingwx64` and `mmkv-kmp-desktop-native-windows-x86_64`.

### Recommended ordering

1. Verify and stage host-specific native artifacts first:
   - macOS desktop-native arm64/x86_64
   - Linux desktop-native x86_64/arm64
   - Windows desktop-native x86_64
   - Linux and Windows KLIBs
2. Publish the primary host artifacts, including `kotlinMultiplatform`, `android`, `desktop`, iOS, and macOS.
3. Inspect the staged repository before release:
   - every coordinate in `desktopNativeRuntimePlatforms` exists,
   - `mmkv-kmp-desktop` POM and Gradle metadata reference those runtime artifacts,
   - `mmkv-kmp` root metadata has available-at variants for all supported targets.
4. Close/release the staging repository only after all artifacts are present.

### Smoke test after staging

Create a temporary consumer project and verify one-dependency resolution:

```kotlin
commonMain.dependencies {
    implementation("com.tencent:mmkv-kmp:<version>")
}
```

For JVM desktop, confirm the runtime classpath includes the desktop-native artifacts transitively and that `MMKV.initialize(rootDir)` can load the native library without adding explicit `runtimeOnly(...)` dependencies.
